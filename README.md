Official package index for [agcli](https://github.com/agcli) — a declarative registry where capsule packages are declared, validated, and published.

## Overview

agcli-registry is a **declarative package registry**. Contributors add small YAML files under `capsules/`; CI merges them into a public index and deploys it to GitHub Pages and Alibaba Cloud OSS.

**This repository:**

- Stores package declarations at `capsules/<group>/<name>.yaml`
- Registers publisher groups in `groups.yaml` with matching `.github/CODEOWNERS` rules
- Validates declarations on every PR (structure, group registration, ownership, release proofs)
- Publishes `index.json` and `index.meta.json` on merge to `main`, with incremental verification via `registry.lock.json`

**This repository does not contain:**

- Capsule source code or tarballs (those live in capsule repos and GitHub Releases)
- `index.json` / `index.meta.json` — generated by CI, listed in `.gitignore`
- Manual edits to `registry.lock.json` in contributor PRs — updated by the publish workflow on `main`

## How it works

```text
  Contributor                        CI / automation                      Endpoints
 ────────────────                   ──────────────────                 ──────────
  1. Onboard group (Issue) ──▶  Maintainer PR: groups.yaml + CODEOWNERS
  2. Add capsule YAML ──────▶  PR ──▶  check-capsule-ownership.yml
                                    validate-index.yml
                                    │
                                    ▼ (checks pass + review)
                                  Merge to main
                                    │
                                    ▼
                                  publish-index.yml
                                    ├─ merge → index.json + registry.lock.json
                                    ├─ generate index.meta.json + sign index.json
                                    ├─ deploy-pages ──────▶  https://registry.agcli.dev/
                                    └─ sync-oss ──────────▶  Alibaba Cloud OSS
                                    │
                                    ▼ (on success)
                                  sync-capsules-to-oss.yml (mirror tarballs)
```

On a pull request, **validate-index** trusts release proofs from the base branch lock and **re-downloads only changed** `group/name` entries. On **main**, publish rebuilds the index, commits an updated lock when needed, and deploys.

See [docs/ci-workflows.md](docs/ci-workflows.md) for workflow details.

## Quick start

### First time publishing?

Your team needs a **group** before adding packages:

1. **Onboard the group** — Open an Issue with **Apply for New Group Onboarding**. A maintainer merges a PR that adds `groups.yaml` and CODEOWNERS entries.
2. **Declare your package** — After onboarding merges, fork the repo and add `capsules/<your-group>/<name>.yaml`.

Full guide: [docs/onboard-new-group.md](docs/onboard-new-group.md)

### Already have a group?

1. Fork this repository
2. Create `capsules/<your-group>/<name>.yaml`
3. Open a PR — CI validates automatically

Full guide: [docs/contributing.md](docs/contributing.md)

## Package declaration

Each package is one YAML file. You declare **identity and source**; CI derives download URLs and integrity from your GitHub Release layout.

```yaml
version: 1.0.0
summary: "Short description for search"
repository: "https://github.com/myteam/hello-world"
```

Optional: `name` in YAML must match the filename if present.

**Release layout (enforced by CI):**

| Asset | URL pattern |
|-------|-------------|
| Tarball | `https://github.com/<owner>/<repo>/releases/download/<name>/v<version>/capsule.tar.gz` |
| SHA256 file | `.../capsule.tar.gz.sha256` (single line, 64 lowercase hex chars) |

The tarball must contain `capsule.yaml` with `group`, `name`, and `version` matching the registry path and YAML fields. See [docs/capsule-release-guide.md](docs/capsule-release-guide.md).

Key rules:

- `group` comes from the directory name; `name` from the filename (without `.yaml`)
- `repository` must be `https://github.com/<owner>/<repo>`
- All packages from the same `repository` must share the same `group`
- `publisher_tier` is taken from `groups.yaml` (`tier`), not from package YAML

Authoritative schema: [docs/registry-yaml-spec.md](docs/registry-yaml-spec.md). Step-by-step submission: [docs/contributing.md](docs/contributing.md).

## Repository structure

```text
agcli-registry/
├── capsules/                 # Package declarations (one YAML per package)
│   └── <group>/
│       └── <name>.yaml
├── groups.yaml               # Group registry (tier + owners)
├── registry.lock.json        # Verified release cache (CI updates on main)
├── scripts/                  # registry.sh, ownership checks, OSS sync
├── .github/
│   ├── workflows/            # validate, ownership, publish, audit, OSS sync
│   ├── CODEOWNERS            # Per-group review (must match groups.yaml)
│   └── ISSUE_TEMPLATE/       # Group onboarding form
└── docs/                     # Public documentation
```

## Public endpoints

| Endpoint | Description |
|----------|-------------|
| `https://registry.agcli.dev/index.json` | Merged package index |
| `https://registry.agcli.dev/index.json.asc` | Detached OpenPGP signature over `index.json` |
| `https://registry.agcli.dev/index.meta.json` | Metadata: `hash`, `updated_at`, `signing`, `schema_version` |

Clients should (1) verify `index.json` with the registry signing key ([`keys/registry-signing.pub`](keys/registry-signing.pub)), then (2) confirm `index.meta.json.hash` matches the SHA-256 of `index.json` raw bytes. See [`keys/README.md`](keys/README.md).
